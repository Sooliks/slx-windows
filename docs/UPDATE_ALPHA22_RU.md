# Обновление SLX VPN до 0.1.0-alpha.22

Дата подготовки: 25 октября 2026. Основа — опубликованная alpha.21, коммит
`0b2979d5358b5467516dd18738379f3707d744ee`, тег `v0.1.0-alpha.21`.

## Что установлено по диагностике

Владелец сообщил о надписи «Переподключаемся» после запуска Steam. Его отчёт
alpha.21 показывает `Connected`, `Protection: True`, `Probe passed: True`,
`Health incidents: 10, retained: 10` и не содержит `Recovery`. Все десять
зарегистрированных эпизодов закончились подтверждением связи с сохранением
туннеля. Причина неудачных первичных запросов и связь со Steam не установлены.

Последний эпизод указан как `2026-10-25T03:51:25Z` (06:51 по Москве), а отчёт
снят в `04:09:13Z` (07:09 по Москве). Счётчики накоплены за время работы службы;
их нельзя автоматически приписывать последнему запуску приложения.

Проверка DNS относится к более раннему запуску туннеля: первая попытка получила
таймаут за 3006 мс, вторая — корректный ответ за 62 мс. В обеих указан принадлежащий
SLX маршрут `/32` с метрикой маршрута 0. Это успешная проверка DNS после повтора,
а не `RouteMismatch`. Результат владельца не подтверждает работу на ПК друга.

## Что меняет alpha.22

Повторная проверка доступности имеет отдельное состояние `Checking` и подпись
«Проверяем соединение». Защита и работающий туннель сохраняются; `ProbePassed`
остаётся `false`, пока проверка не завершена. При успехе возвращается «Подключено»
с прежним временем начала соединения. Настоящее восстановление отображается как
«Переподключаемся» и выполняется прежним способом.

В «Помощь → Скопировать диагностику» добавлены результаты первичной, повторной
и альтернативной проверок из уже существующих наблюдений службы: фиксированная
цель, категория результата, длительность и HTTP-код при наличии. Строки называются
`Health primary`, `Health repeat` и `Health alternate`; отсутствующие наблюдения
не выводятся. `Connected UTC` показывает известное время начала подключения.
Личная ссылка, адреса, список программ и текст исключений не записываются.

Проверки, интервалы, таймауты, DNS и маршруты приложений сохраняются. Выключение
Telegram в SLX меняет выбор для новых соединений; уже открытый сеанс может
сохранить прежний маршрут до полного выхода из Telegram.

Это подготовленные исходники. Текущие результаты проверок alpha.22 и оставшиеся
ограничения записаны в [VERIFICATION.md](VERIFICATION.md). Успешная сборка alpha.21
не заменяет проверку и публикацию нового коммита.

## 1. Применить изменённые файлы

Скопируйте содержимое папки `slx-windows` из changed-архива в существующую папку
Windows-проекта, сохраняя пути и заменяя файлы. Патч рассчитан на alpha.21.
Незакоммиченные собственные изменения предварительно сохраните отдельно.
Полный архив содержит все исходники для сохранения контекста. Удалять исходные
файлы при применении этого исправления не требуется.

Этот патч относится к `Sooliks/slx-windows`. Ранее подготовленный web alpha.31
обновляет сайт отдельно; его файлы в Windows-проект не копируются.

## 2. Отправить исходники в GitHub

Откройте Windows PowerShell и выполните:

```powershell
Set-Location "$env:USERPROFILE\Desktop\slx-windows" -ErrorAction Stop

[xml]$buildProps = Get-Content .\Directory.Build.props -Raw
if ($buildProps.Project.PropertyGroup.Version -ne '0.1.0-alpha.22') {
    throw 'Открыта другая папка или исправление alpha.22 ещё не применено'
}

git status --short
git diff --stat
git remote -v
```

Убедитесь, что `origin` указывает на `https://github.com/Sooliks/slx-windows.git`,
а diff относится к этому исправлению. Затем выполните:

```powershell
git add -- Directory.Build.props PROJECT_SPEC.md README.md docs src tests
if ($LASTEXITCODE -ne 0) { throw 'Не удалось добавить исправление статуса проверки' }

git commit -m 'Release alpha.22: distinguish health checks from tunnel recovery'
if ($LASTEXITCODE -ne 0) { throw 'Не удалось создать коммит' }

git push origin HEAD:main
if ($LASTEXITCODE -ne 0) { throw 'Не удалось отправить изменения в GitHub' }
```

Изменение `Directory.Build.props` запускает существующий workflow
`Publish Windows prerelease`. Сборка выполняется в GitHub на Windows; для этого
push локальные SDK, PowerShell 7 и Inno Setup не требуются. Точный предыдущий тег
для исходников — alpha.21. Ручной тег, force-push и замена старых assets не нужны.

## 3. Дождаться публикации

Откройте [GitHub Actions](https://github.com/Sooliks/slx-windows/actions).
Дождитесь успешного запуска именно для нового коммита: Windows-тесты, сборка
установщика, проверка чистоты исходников, упаковка и публикация должны завершиться.
При ошибке исправьте причину по журналу, сохранив проверки. После нового коммита
запускайте workflow для него: устаревший запуск не должен публиковать выпуск.

После успешной публикации на [странице alpha.22](https://github.com/Sooliks/slx-windows/releases/tag/v0.1.0-alpha.22)
должны находиться:

- `SLX-VPN-0.1.0-alpha.22-win-x64-setup.exe`;
- `SLX-VPN-0.1.0-alpha.22-source-full.zip`;
- `SLX-VPN-0.1.0-alpha.22-source-changed.zip`;
- `DELETIONS.txt`;
- `provenance.json`;
- `SHA256SUMS.txt`.

Выпуск остаётся prerelease в текущем публичном канале SLX. Приложение и сайт
умеют выбирать следующий номер alpha; фактическую свежесть ссылки сайта
проверяйте отдельно, поскольку у сайта есть свой кэш.

```powershell
curl.exe --noproxy "*" --max-time 20 -sS -D - -o NUL -H "Cache-Control: no-cache" "https://slxvpn.com/download/windows" |
    Select-String '^(HTTP/|Location:|Cache-Control:|X-SLX-Release-)'
```

Ожидаемый `Location` содержит `releases/download/v0.1.0-alpha.22/SLX-VPN-0.1.0-alpha.22-win-x64-setup.exe`.
Если сайт ещё выдаёт прежний номер, используйте опубликованный установщик GitHub.
Повторный push тех же файлов не обновляет кэш сайта.

## 4. Установить и проверить

Перед установкой нажмите «Отключиться», дождитесь подтверждённого отключения
и полностью выйдите из SLX через трей. Установите alpha.22 поверх текущей версии.
**Служба и интерфейс обновляются вместе:** `Checking` — новое значение состояния,
поэтому заменять один EXE вручную нельзя. Настройки и подписка сохраняются.

1. Убедитесь, что интерфейс показывает `0.1.0-alpha.22`. Проверьте обычное
   подключение и отключение в используемом режиме и обе темы/языки, если они нужны.
2. Если снова возникнет проверка, ожидайте «Проверяем соединение» с доступной
   кнопкой «Отключиться». Успешное подтверждение должно сохранить время начала
   подключения. Не вызывайте искусственный сбой изменением брандмауэра или DNS.
3. Скопируйте диагностику до запуска Steam и после события при неизменных
   настройках SLX. Сравните время, `Connected UTC`, `Health incidents`, `retained`,
   `Recovery`, `Health primary`, `Health repeat` и `Health alternate`; отметьте,
   загружал ли Steam обновления.
4. Для Telegram оставьте его переключатель выключенным, дождитесь применения,
   полностью выйдите из Telegram через трей и запустите снова. Проверьте новое
   сообщение/медиа. IP в выбранном браузере показывает маршрут браузера, а не
   Telegram. Если мессенджер работает, отдельно сравните с полностью отключённым
   SLX и проверьте собственный прокси Telegram.
5. Сохраните проверку на ПК друга из [руководства alpha.21](UPDATE_ALPHA21_RU.md):
   его подключение и DNS, работа выбранных приложений, CS2 вне списка, обычный
   Интернет после явного отключения. Новый статус не заменяет эту приёмку.

Сведения о первичном таймауте показывают вид неудачи, но сами по себе не
устанавливают виновника. Реальные HY2/VLESS, WFP/TUN, обновление установленной
службы, Windows 10 и чистая машина остаются отдельными системными проверками.

## Локальная сборка и откат

На Windows с SDK из `global.json` и PowerShell 7:

```powershell
pwsh -NoProfile -File .\scripts\verify.ps1
pwsh -NoProfile -File .\scripts\build.ps1 -Candidate
```

Кандидат предназначен для проверки и не публикуется. Выпуск собирается workflow
из чистого коммита. Действующие проверки и доверие к закреплённым компонентам
сохраняются.

Для отката явно отключите VPN, выйдите из SLX и установите опубликованную
alpha.21 целиком. Миграция настроек/БД не требуется. В alpha.21 повторная
проверка снова будет отображаться общей надписью «Переподключаемся».
