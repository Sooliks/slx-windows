# Обновление SLX VPN до 0.1.0-alpha.20

Дата подготовки: 24 октября 2026. Основа — опубликованная alpha.19, коммит `522cb9ec9c4f13ef2cd71d20c4918c76fbdfc37c`, тег `v0.1.0-alpha.19`.

## Что исправляется

На скриншоте друга установлена alpha.19; выбран Hysteria2, режим приложений и Discord, отображается `VPN_DNS_FAILED`. Этот код выдаётся после успешной проверки HTTPS через VPN и готовности адаптера, на отдельной проверке DNS. Скриншот не определяет, был ли причиной таймаут DNS, ошибка сокета или маршрут Windows.

Воспроизведён дефект конфигурации Xray 26.9.9: при `disableFallback=true` второй указанный DNS-сервер не использовался. Простого включения перебора недостаточно: ожидание первого сервера занимает до четырёх секунд, а одна попытка проверки — три секунды. Alpha.20 разрешает параллельные запросы к тем же двум HTTPS-серверам через VPN. Если оба не отвечают, подключение не объявляется успешным.

Дополнительно проверяется обычный маршрут DNS в адаптер SLX и полный ответ DNS. Новая диагностика содержит до трёх результатов с числовыми кодами без адресов, имён адаптеров, профилей и личной ссылки. Настройки физического DNS, маршруты и WFP не изменяются; принудительное направление только проверочного сокета в TUN не используется.

## 1. Применить и отправить исходники

Скопируйте содержимое папки `slx-windows` из `SLX-VPN-0.1.0-alpha.20-source-changed.zip` в существующий проект с заменой файлов. Патч рассчитан на `522cb9e`; удалений исходников нет. Полный архив содержит весь проект. Сохраните свои отдельные незакоммиченные изменения перед заменой.

В обычном Windows PowerShell:

```powershell
Set-Location "$env:USERPROFILE\Desktop\slx-windows" -ErrorAction Stop

git diff --stat
git add -- Directory.Build.props PROJECT_SPEC.md README.md docs src tests
if ($LASTEXITCODE -ne 0) { throw 'Не удалось добавить исправление DNS.' }

git commit -m 'Release alpha.20: resilient VPN DNS and connection diagnostics'
if ($LASTEXITCODE -ne 0) { throw 'Не удалось создать коммит.' }

git push origin HEAD:main
if ($LASTEXITCODE -ne 0) { throw 'Не удалось отправить изменения.' }
```

Добавляйте эти каталоги, только если изменения относятся к патчу. Force-push не требуется. Изменение версии автоматически запускает существующий Windows workflow; локальные SDK и Inno Setup для публикации не нужны. Исходники сравниваются с alpha.19, старые выпуски сохраняются. Ранее прямая запись подключением этой сессии была отклонена GitHub (`403 Resource not accessible by integration`), поэтому отправка выполняется доступом владельца из его рабочей копии.

## 2. Выпустить в публичный канал и проверить сборку

Проверьте [GitHub Actions](https://github.com/Sooliks/slx-windows/actions). После успешных Windows-тестов, сборки и публикации на [странице alpha.20](https://github.com/Sooliks/slx-windows/releases/tag/v0.1.0-alpha.20) должны появиться шесть файлов выпуска, включая `SLX-VPN-0.1.0-alpha.20-win-x64-setup.exe`.

Это выпуск в текущий публичный канал SLX: `alpha.20` остаётся предварительной версией, которую видят пользователи alpha.19. Создавать тег, вручную загружать установщик или менять сервер сайта для запуска этого workflow не нужно.

1. Откройте запуск `Publish Windows prerelease` с коммитом `Release alpha.20: resilient VPN DNS and connection diagnostics`.
2. Дождитесь зелёного результата всего запуска. Отдельно завершённый шаг сборки ещё не означает публикацию: должны пройти Windows-тесты, сборка установщика, упаковка и `Publish immutable prerelease assets`.
3. Откройте страницу alpha.20 и убедитесь, что там есть установщик, `source-full.zip`, `source-changed.zip`, `DELETIONS.txt`, `provenance.json` и `SHA256SUMS.txt` с версией alpha.20 в именах версионных файлов.
4. Если запуск красный, откройте упавший шаг и передайте ссылку на запуск или его журнал. Исправление причины должно пройти те же проверки; менять теги или отключать проверки не требуется.

### Обновить оба ПК

В alpha.19 можно нажать «Настройки → Обновления приложения → Проверить обновления» и затем отдельно скачать и установить предложенную alpha.20. Либо скачайте установщик напрямую со страницы выпуска. Публикация на GitHub не доказывает немедленное обновление кеша кнопки сайта.

Перед установкой отключите VPN, дождитесь подтверждённого отключения и полностью выйдите из SLX через трей. Запустите новый установщик поверх текущей версии: служба и интерфейс должны обновиться вместе. Настройки и подписка сохраняются.

### Проверить, подхватил ли сайт новую версию

После успешной публикации выполните в PowerShell:

```powershell
curl.exe --noproxy "*" --max-time 20 -sS -D - -o NUL "https://slxvpn.com/download/windows" |
    Select-String '^(HTTP/|Location:)'
```

В `Location` должен быть путь `releases/download/v0.1.0-alpha.20/SLX-VPN-0.1.0-alpha.20-win-x64-setup.exe`. Если там старая версия, используйте прямой установщик со страницы alpha.20: GitHub-релиз готов, а переключение сайта требует отдельной проверки. Повторять commit/push того же патча для этого не нужно. У этой сессии нет исходников обработчика сайта, поэтому точный срок его кеширования не подтверждён.

## 3. Проверка на ПК друга

1. Убедитесь, что в интерфейсе указана `0.1.0-alpha.20`.
2. Повторите подключение с тем же способом и теми же приложениями, на которых возникла ошибка.
3. Если подключение удалось, проверьте нужные приложения и отдельную работу CS2. Эти результаты нельзя вывести из успешной сборки.
4. Если ошибка повторилась, сразу откройте «Помощь → Скопировать диагностику» и передайте полный полученный текст. Строки `DNS attempt` позволят различить `Timeout`, `SocketError`, `Rejected`, `InvalidResponse`, `RouteMismatch` и `RouteUnavailable`; сырые пакеты или личная ссылка не нужны.

`route=OtherInterface` указывает, что проверенный обычный маршрут не принадлежал адаптеру SLX; это само по себе не называет виновный адаптер или программу. `socket=10013` означает отказ в доступе сокету, а не доказанную блокировку конкретным антивирусом. Ручная смена DNS физического адаптера для применения этого исправления не нужна.

Для локальной проверки на Windows с закреплённым SDK и PowerShell 7 используйте `pwsh -NoProfile -File .\scripts\verify.ps1`. Кандидат собирается командой `pwsh -NoProfile -File .\scripts\build.ps1 -Candidate`; он не допускается к публикации. Фактически выполненные проверки и ограничения записаны в [VERIFICATION.md](VERIFICATION.md).
