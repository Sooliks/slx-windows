# Обновление SLX VPN до 0.1.0-alpha.21

Дата подготовки: 25 октября 2026. Основа — опубликованная alpha.20, коммит
`9cd73831292c8e8ba34327ead0039969c70cea7d`, тег `v0.1.0-alpha.20`.

## Что установлено по диагностике

На ПК друга alpha.20 трижды получила `RouteMismatch`, `route=OtherInterface`,
`0 ms`. Проверка отказала до отправки DNS-запроса: обычный маршрут Windows к
проверяемому DNS-адресу не принадлежал адаптеру SLX. Поэтому этот отчёт не
показывает таймаут DNS или сбой Hysteria2. Конкретный конкурирующий интерфейс
и причина выбора маршрута пока не установлены. `Disconnected / Protection: False`
означает, что служба сообщила о завершённом отключении после неудачной попытки.

Alpha.21 добавляет в конфигурацию существующего Xray точные маршруты
`1.1.1.1/32` и `2606:4700:4700::1111/128` на его TUN, сохраняя общие маршруты.
Проверка ограниченно ждёт готовности маршрута в прежнем бюджете времени.
Чужой маршрут по-прежнему не разрешает отправить проверку DNS или показать
«Подключено». Ошибка маршрута теперь различается кодом `VPN_DNS_ROUTE_FAILED`;
поля `prefix_length` и `route_metric` дополняют безопасную диагностику.

Это подготовленные исходники, а не подтверждение публикации или успешной
установки на ПК друга. Фактические команды, результаты и оставшиеся ограничения
записаны в [VERIFICATION.md](VERIFICATION.md).

## 1. Применить изменённые файлы

Скопируйте содержимое папки `slx-windows` из changed-архива в существующую папку
Windows-проекта, сохраняя пути и заменяя файлы. Патч рассчитан на alpha.20.
Незакоммиченные собственные изменения предварительно сохраните отдельно.
Полный архив содержит исходники для сохранения контекста. Удалять исходные файлы
при применении этого исправления не требуется.

Ранее подготовленный **web 0.14.0-alpha.31** — отдельное исправление сайта.
Этот патч применяется к `Sooliks/slx-windows`; веб-файлы сюда копировать не нужно.
Для публикации alpha.21 новые переменные сайта, изменения БД, VPN-узлов или
ручная смена DNS физического адаптера не требуются.

## 2. Отправить исходники в GitHub

Откройте Windows PowerShell и выполните:

```powershell
Set-Location "$env:USERPROFILE\Desktop\slx-windows" -ErrorAction Stop

[xml]$buildProps = Get-Content .\Directory.Build.props -Raw
if ($buildProps.Project.PropertyGroup.Version -ne '0.1.0-alpha.21') {
    throw 'Открыта другая папка или исправление alpha.21 ещё не применено'
}

git status --short
git diff --stat
git remote -v
```

Убедитесь, что `origin` указывает на `https://github.com/Sooliks/slx-windows.git`,
а diff относится к применённому исправлению. Затем:

```powershell
git add -- Directory.Build.props PROJECT_SPEC.md README.md docs/ARCHITECTURE.md docs/NETWORK.md docs/RELEASE_NOTES.md docs/RELEASE_NOTES_ALPHA21.md docs/UPDATE_ALPHA21_RU.md docs/VERIFICATION.md src tests
if ($LASTEXITCODE -ne 0) { throw 'Не удалось добавить исправление маршрутов DNS' }

git commit -m 'Release alpha.21: DNS host routes and bounded route readiness'
if ($LASTEXITCODE -ne 0) { throw 'Не удалось создать коммит' }

git push origin HEAD:main
if ($LASTEXITCODE -ne 0) { throw 'Не удалось отправить изменения в GitHub' }
```

Локальные SDK, PowerShell 7 и Inno Setup для этого push не нужны. Изменение
`Directory.Build.props` запускает существующий workflow `Publish Windows prerelease`.
Точный base — alpha.20; прежний выпуск сохраняется. Force-push и ручной тег не нужны.

## 3. Дождаться выпуска

Откройте [GitHub Actions](https://github.com/Sooliks/slx-windows/actions).
Дождитесь успешного запуска для **нового коммита**: должны пройти Windows-тесты,
сборка установщика, проверка чистоты исходников, упаковка и публикация.

После успеха на [странице alpha.21](https://github.com/Sooliks/slx-windows/releases/tag/v0.1.0-alpha.21)
должны появиться шесть файлов:

- `SLX-VPN-0.1.0-alpha.21-win-x64-setup.exe`;
- `SLX-VPN-0.1.0-alpha.21-source-full.zip`;
- `SLX-VPN-0.1.0-alpha.21-source-changed.zip`;
- `DELETIONS.txt`;
- `provenance.json`;
- `SHA256SUMS.txt`.

Выпуск остаётся prerelease в текущем публичном канале SLX. Существующие приложение
и сайт умеют выбирать следующую alpha по номеру; отдельная правка номера на сайте
для выбора alpha.21 не требуется. Свежесть фактической ссылки проверяется отдельно.
Если workflow упал, исправляйте причину по журналу; проверки не отключайте.
При следующем исправляющем коммите запускайте workflow именно для него:
устаревшему запуску запрещено публиковать после продвижения `main`.

## 4. Обновить владельца и друга

В alpha.20 откройте «Настройки → Обновления приложения → Проверить обновления».
После публикации можно отдельно скачать и установить alpha.21. Альтернативно
используйте установщик с её страницы GitHub Releases.

Перед установкой отключите VPN, дождитесь подтверждённого отключения и полностью
выйдите из SLX через трей. Запустите установщик поверх текущей версии: служба
и интерфейс должны обновиться вместе, настройки и подписка сохраняются.

Проверка кнопки сайта после публикации:

```powershell
curl.exe --noproxy "*" --max-time 20 -sS -D - -o NUL -H "Cache-Control: no-cache" "https://slxvpn.com/download/windows" |
    Select-String '^(HTTP/|Location:|Cache-Control:|X-SLX-Release-)'
```

В `Location` ожидается `releases/download/v0.1.0-alpha.21/SLX-VPN-0.1.0-alpha.21-win-x64-setup.exe`.
Диагностические `X-SLX-Release-*` есть только после отдельного обновления сайта.
Если ссылка ещё старая, используйте опубликованный установщик GitHub; повторный
push тех же исходников не обновляет кэш сайта.

## 5. Проверить исправление на установленных ПК

1. Проверьте номер `0.1.0-alpha.21` в интерфейсе после установки.
2. У друга повторите тот же Hysteria2, режим «Приложения» и Discord. На рабочем
   ПК владельца проверьте прежний успешный сценарий. Отдельно проверьте «Весь ПК».
3. Проверьте DNS и нужные приложения после успешного подключения, затем работу
   CS2 вне выбранного списка. Успешная сборка этих результатов не доказывает.
4. Нажмите «Отключиться». Убедитесь в подтверждённом выключении, неактивной защите
   и обычной работе Интернета; повторите подключение и отключение.
5. При ошибке сразу скопируйте диагностику из «Помощь». Сохраните все строки
   `DNS attempt`, включая `route`, `prefix_length`, `route_metric` и время;
   личная ссылка и полный список сетевых адаптеров не нужны.

Для технической приёмки маршрутов используйте **только чтение** ниже. Сначала,
при отключённом VPN, в одной PowerShell-сессии сохраните исходные строки:

```powershell
$dnsPrefixes = @('1.1.1.1/32', '2606:4700:4700::1111/128')
$routesBefore = @(Get-NetRoute -PolicyStore ActiveStore |
    Where-Object { $_.DestinationPrefix -in $dnsPrefixes } |
    Select-Object InterfaceIndex, InterfaceAlias, DestinationPrefix, NextHop, RouteMetric)
```

После успешного подключения выполните:

```powershell
Get-NetRoute -PolicyStore ActiveStore |
    Where-Object { $_.DestinationPrefix -in $dnsPrefixes } |
    Select-Object InterfaceIndex, InterfaceAlias, DestinationPrefix, NextHop, RouteMetric
```

Ожидаются обе host-route строки на `SLX VPN`. Уже существовавшие строки других
интерфейсов должны сохраниться. Наличие маршрутов само по себе не доказывает
фактический DNS-ответ: это дополняет успешное подключение и проверку приложений.
Если подключение сразу отменилось с ошибкой, служба уже очищает свой туннель;
отсутствие его строк после отказа нельзя считать снимком момента DNS-проверки.

После «Отключиться», при неизменной физической сети:

```powershell
$routesAfter = @(Get-NetRoute -PolicyStore ActiveStore |
    Where-Object { $_.DestinationPrefix -in $dnsPrefixes } |
    Select-Object InterfaceIndex, InterfaceAlias, DestinationPrefix, NextHop, RouteMetric)
$routesBefore
$routesAfter
```

Сравните исходные и итоговые строки. Ожидаются удаление принадлежащих SLX host routes
и сохранность исходных чужих строк. Если исходных маршрутов не было, после отключения
не должно остаться строк SLX для этих префиксов. Сверьте также, что настройки DNS
физического адаптера остались прежними. Не удаляйте конкурирующие маршруты вручную
для получения успешного результата проверки.

## Локальная сборка и откат

На Windows с SDK из `global.json` и PowerShell 7:

```powershell
pwsh -NoProfile -File .\scripts\verify.ps1
pwsh -NoProfile -File .\scripts\build.ps1 -Candidate
```

Кандидат не допускается к публикации. Фактический unsigned prerelease собирается
workflow из проверенного чистого коммита. Нативная приёмка TUN/WFP и чужих маршрутов
остаётся отдельной от unit-тестов и компиляции.

Для отката сначала явно отключите VPN и выйдите из SLX, затем установите прежнюю
опубликованную alpha.20. Данные совместимы; отдельная миграция БД или настроек
не нужна. Старый способ маршрутизации и его ограничения при этом возвращаются.
