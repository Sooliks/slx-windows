# Обновление SLX VPN до 0.1.0-alpha.19

Дата подготовки: 24 октября 2026. Основа — опубликованная alpha.18, коммит `ccb1b71fb0a5fd6842741298933003380db408c2`, тег `v0.1.0-alpha.18`.

## Причина и исправление

На ПК владельца запрос списка версий вернул HTTP 200 и остаток лимита GitHub 56/60, но не успел закончиться за 15 секунд: получено 126 432 из 149 771 байта. Запрос контрольных сумм прошёл с ответами 302 и 200. Формат релиза alpha.18 совместим с проверяющим кодом alpha.17; сбой списка подтверждён именно при чтении тела ответа.

Alpha.19 запрашивает сжатый список версий (в проверенном ответе 23 874 байта вместо 149 771), оставляет поддержку обычного ответа и даёт всей проверке до 30 секунд. Ограничения размера, безопасная распаковка и проверки источника/контрольных сумм сохраняются. Интерфейс различает таймаут и некорректные данные. Изменение не обещает доступность GitHub при любой сетевой неисправности.

## 1. Применить и отправить исходники

Скопируйте содержимое папки `slx-windows` из `SLX-VPN-0.1.0-alpha.19-source-changed.zip` в существующий проект с заменой файлов. Патч рассчитан на `ccb1b71`, удалений исходников нет. Полный архив содержит весь актуальный исходный проект. Сохраните собственные незакоммиченные изменения перед заменой.

Выполните из корня своей Git-копии в обычном PowerShell:

```powershell
git diff --stat
git add -- Directory.Build.props PROJECT_SPEC.md README.md docs src tests
if ($LASTEXITCODE -ne 0) { throw 'Не удалось добавить исправление обновления.' }

git commit -m 'Release alpha.19: compressed update checks and timeout feedback'
if ($LASTEXITCODE -ne 0) { throw 'Не удалось создать коммит.' }

git push origin HEAD:main
if ($LASTEXITCODE -ne 0) { throw 'Не удалось отправить изменения.' }
```

Добавляйте эти каталоги, только если изменения в них относятся к применённому патчу. При конфликте истории совместите изменения; force-push не требуется.

Изменение `Directory.Build.props` автоматически запускает существующий workflow [Publish Windows prerelease](https://github.com/Sooliks/slx-windows/actions). Он проверит исходники на Windows, соберёт установщик, упакует изменения относительно alpha.18 и опубликует alpha.19. Публикация требует чистого исходного коммита, подходящей предыдущей версии и совпадающих контрольных сумм. Уже опубликованная alpha.18 сохраняется.

Прямая запись через подключение этой сессии ранее была отклонена GitHub (`403 Resource not accessible by integration`); отправка выполняется через доступ владельца из его рабочей копии. Наличие патча не означает успешный Windows-прогон или опубликованную alpha.19.

## 2. Установить выпущенную версию

После успешного workflow на [странице alpha.19](https://github.com/Sooliks/slx-windows/releases/tag/v0.1.0-alpha.19) должны быть шесть файлов: установщик, полный и изменённый ZIP исходников, `DELETIONS.txt`, `provenance.json`, `SHA256SUMS.txt`.

1. Скачайте `SLX-VPN-0.1.0-alpha.19-win-x64-setup.exe` из этого релиза.
2. Отключите VPN, дождитесь подтверждённого отключения и полностью выйдите из SLX через трей.
3. Запустите установщик поверх alpha.17/18. Служба и интерфейс обновляются вместе; сохранённые настройки и подписка остаются.
4. Проверьте версию `0.1.0-alpha.19` и нажмите «Настройки → Обновления приложения → Проверить обновления».

Старый установленный проверяющий код не изменяется от публикации нового релиза. Если его 15-секундная проверка продолжает обрываться, первый переход на alpha.19 выполните вручную через установщик. Проверку переключения кнопки на `slxvpn.com` выполняйте отдельно: публикация в GitHub сама по себе не доказывает обновление кеша сайта.

## 3. Локальная проверка и кандидат

При наличии Windows, PowerShell 7, закреплённого SDK 10.0.401 и Inno Setup 6:

```powershell
pwsh -NoProfile -File .\scripts\verify.ps1
if ($LASTEXITCODE -ne 0) { throw 'Проверки не прошли.' }

pwsh -NoProfile -File .\scripts\build.ps1 -Candidate
if ($LASTEXITCODE -ne 0) { throw 'Кандидат не собран.' }
```

Кандидат находится в `artifacts\candidates\0.1.0-alpha.19\<дата-и-ID>\output`. Он предназначен для ручной проверки и не допускается к публикации. Для автоматического выпуска локальные SDK/Inno Setup не нужны; Windows runner выполняет эти этапы.

Проверьте обновление при том же подключении, на котором запрос раньше обрывался. При недоступном GitHub должна появиться ограниченная по времени ошибка; при доступном списке без новой версии — подтверждённое актуальное состояние. Скачивание/установка по-прежнему требуют отдельных действий пользователя. Результаты команд, фактически выполненные проверки и открытые ограничения записаны в [VERIFICATION.md](VERIFICATION.md).
