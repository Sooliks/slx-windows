# Обновление SLX VPN до 0.1.0-alpha.27

Дата подготовки: 5 ноября 2026. Основа — опубликованная alpha.26, коммит
`9363744d1c883913f0ec1524ced16c619e5ec984`. Кандидат собран из ветки `alpha27`.

## Что установлено по диагностике

05.11 около 19:36–19:41 UTC два разных ПК одновременно теряли связь. ПК1 (Windows 10.0.26300,
режим «Приложения»): `Connecting`, все три проверки Timeout ~3000 мс, `Health incidents 566`,
`Recovery 1 ProbeFailed`; VPN падал 2–3 раза по 5–6 минут, Telegram и стрим в браузере обрывались.
ПК2 (10.0.26200): `Connected`, `Recovery 2 ProbeFailed`, `Health incidents 333`, первичная проверка
gstatic `Tls 2420 мс`, повтор `Success 709 мс`, обе половины IPv4 — `OwnedTunnel /1`.

Причины в коде alpha.26:

1. Один процесс Xray владел и TUN с маршрутами `0.0.0.0/1`/`128.0.0.0/1`, и связью с сервером. Даже в режиме
   «Приложения» весь трафик ПК шёл через этот TUN, а любое восстановление перезапускало процесс вместе с
   адаптером, поэтому рвались соединения всех программ.
2. Восстановление всегда использовало тот же профиль: при блокировке UDP/QUIC провайдером Hysteria2 не
   работал, а перехода на VLESS не было.
3. Ожидание готовности 32 с и паузы до 60 с: возврат сервера замечался с задержкой до ~1,5 мин.
4. Ручное переподключение повторно использовало закреплённый IP и не перерезолвило сервер.
5. Каждый одиночный сбой первичной проверки считался инцидентом, даже если повтор через секунду проходил.

## Что меняет alpha.27

- **Два процесса.** TUN-процесс (адаптер, маршруты, DNS, правила по приложениям) живёт всё подключение.
  Невыбранные приложения идут через него напрямую к провайдеру и не зависят от VPN-сервера. VPN-ядро —
  отдельный процесс без TUN и маршрутов; TUN-процесс обращается к нему через `127.0.0.1` (VLESS, секретный id на
  каждое подключение). Восстановление, падение ядра и смена транспорта перезапускают только ядро.
- **Смена транспорта.** Два неудачных цикла подряд → следующий транспорт того же сервера/локации, по кругу.
  Кандидаты считаются в приложении из подписки: тот же адрес сервера или то же название локации без слов
  `Hysteria2/VLESS/REALITY/XHTTP/SLX`. Чтобы VLESS стал запасным для Hysteria2 другой ноды, у обеих нод в
  подписке должно быть одинаковое название локации.
- **Быстрые повторы:** 1/2/3/5/8/10 с, готовность ядра — до 15 с.
- **«Переподключить»** перерезолвит адреса и начинает с выбранного транспорта.
- **Диагностика:** строки `Transport: hysteria2 (1/2), node: selected server` и `Connection attempt: N, recovery reason: …`.
- **Приложения:** VALORANT (игра + лаунчер + Riot Client) и Claude Code CLI.

Ограничение: если упадёт сам TUN-процесс (не ядро), соединения остальных программ, шедшие через него,
прервутся, как раньше. Это локальный процесс без зависимости от сервера; при проверке он не перезапускается.

## Как проверить перед публикацией (обязательно)

1. Сборка и тесты: `./scripts/verify.ps1` (ожидается exit 0).
2. Кандидат установщика: `./scripts/build.ps1`, установить на этом ПК (VPN один раз отключится).
3. В PowerShell от администратора: `./scripts/acceptance-alpha27.ps1 -Step Build`, добавить
   `artifacts\acceptance\alpha27\egress-Selected\SlxEgressSelected.exe` в выбранные приложения, подключиться
   в режиме «Приложения».
4. `./scripts/acceptance-alpha27.ps1 -Step All -ServerHost <адрес сервера выбранной локации>` — проверяет:
   выбранное приложение выходит через VPN по TCP и UDP; невыбранное — через провайдера; невыбранное не
   теряет ни одного запроса, пока ядро убивают и оно восстанавливается; при временной блокировке UDP к серверу
   выбранное приложение возвращается через другой транспорт. Правило брандмауэра удаляется в `finally`.
5. После шага 4 скопировать диагностику: `Transport` должен показать `vless-*`.

Если что-то не прошло — не публиковать, откатиться на alpha.26 установщиком с GitHub.
