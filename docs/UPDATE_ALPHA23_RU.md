# Обновление SLX VPN до 0.1.0-alpha.23

Основа — опубликованная alpha.22, коммит `f694b51c8a815ce041fe67b26c8e21627aaa5cda`, тег `v0.1.0-alpha.22`.

Исходники уже изменены в `C:\Users\xls\Desktop\slx-windows`. На этом ПК повторно распаковывать ZIP не нужно. Changed-архив предназначен для переноса на чистую alpha.22 с сохранением путей; полный архив — для контекста. Свои незакоммиченные изменения перед переносом сохраните отдельно. Файлы сайта сюда не копируются.

По прямому поручению владельца Codex выполняет commit/push в `main` и выпуск через существующий GitHub Actions. Ниже сохранены команды для воспроизведения процесса; после успешного выпуска повторять их не требуется. Текущие проверки перечислены в [VERIFICATION.md](VERIFICATION.md), изменения — в [RELEASE_NOTES.md](RELEASE_NOTES.md).

## Отправить обновление

В PowerShell проверьте папку, версию, ветку, origin и состав изменений:

```powershell
Set-Location "$env:USERPROFILE\Desktop\slx-windows" -ErrorAction Stop
[xml]$buildProps = Get-Content .\Directory.Build.props -Raw
if ($buildProps.Project.PropertyGroup.Version -ne '0.1.0-alpha.23') {
    throw 'Открыта другая папка или alpha.23 не применена'
}
git status --short
git diff --stat
git remote -v
git branch --show-current
git diff --check
if ($LASTEXITCODE -ne 0) { throw 'Проверьте diff перед выпуском' }
```

Ожидается ветка `main`, origin `Sooliks/slx-windows` и только нужные изменения. Затем:

```powershell
git add -- Directory.Build.props PROJECT_SPEC.md README.md docs src tests
if ($LASTEXITCODE -ne 0) { throw 'Не удалось подготовить изменения alpha.23' }
git commit -m 'Release alpha.23: validate tunnel routes and stabilize app routing'
if ($LASTEXITCODE -ne 0) { throw 'Не удалось создать коммит' }
git push origin HEAD:main
if ($LASTEXITCODE -ne 0) { throw 'Не удалось отправить коммит' }
```

Изменение версии запускает [Publish Windows prerelease](https://github.com/Sooliks/slx-windows/actions/workflows/release.yml). Workflow проверяет точный предыдущий тег alpha.22, выполняет Windows-тесты, собирает установщик из чистого коммита и публикует шесть assets. Не создавайте тег вручную и не заменяйте assets старого выпуска. Если push отклонён, сохраните локальную работу и согласуйте изменения с `origin/main`; force-push не нужен.

## Проверить публикацию

Дождитесь успешного workflow именно для нового коммита. На [странице alpha.23](https://github.com/Sooliks/slx-windows/releases/tag/v0.1.0-alpha.23) должны появиться:

- `SLX-VPN-0.1.0-alpha.23-win-x64-setup.exe`;
- `SLX-VPN-0.1.0-alpha.23-source-full.zip` и `SLX-VPN-0.1.0-alpha.23-source-changed.zip`;
- `DELETIONS.txt`, `provenance.json`, `SHA256SUMS.txt`.

Архивы с `handoff` в имени не являются этими release-assets: они снимали рабочее дерево до коммита и не содержат установщик. При ошибке CI исправьте причину по журналу без отключения проверок.

Сайт имеет собственный кэш. После публикации можно проверить редирект:

```powershell
curl.exe --noproxy "*" --max-time 20 -sS -D - -o NUL -H "Cache-Control: no-cache" "https://slxvpn.com/download/windows" |
    Select-String '^(HTTP/|Location:|Cache-Control:|X-SLX-Release-)'
```

Ожидаемый `Location` содержит `v0.1.0-alpha.23/SLX-VPN-0.1.0-alpha.23-win-x64-setup.exe`. Если сайт пока отдаёт прежнюю версию, используйте опубликованный установщик GitHub. Этот Windows-патч не развёртывает исправление кэша сайта.

## Установить и проверить на проблемном ПК

Явно отключите VPN, дождитесь подтверждения и полностью выйдите из SLX через трей. Установите новый выпуск поверх текущего: интерфейс и служба обновляются вместе. Отдельные EXE вручную не заменяйте. Данные подписки и пользовательские настройки не мигрируют.

1. Убедитесь, что установлена alpha.23. Сохраните диагностику до подключения, затем нажмите «Подключиться». Если действие долго выполняется, скопируйте диагностику прямо в этот момент; после результата сохраните ещё одну.
2. Сравните `UI operation`, `Service observation`, `Service read UTC`, `Phase`, `Protection`, `Probe passed`, `Code` и `Traffic route`. `Observed UTC` относится к публикации состояния службы, DNS-время — к отдельной проверке. Одно лишь успешное DNS-наблюдение не доказывает трафик приложений.
3. Проверьте новую загрузку в выбранном приложении, затем режим «Весь ПК». Откройте новые соединения; старые сеансы приложения могут сохранять прежний маршрут. Для Telegram полностью выйдите через его трей. Проверка IP в браузере относится к этому браузеру.
4. Если получен `VPN_TRAFFIC_ROUTE_FAILED`, сохраните диагностику: она покажет конфликт обычных маршрутов отдельно от DNS. Код не устанавливает конкретную стороннюю программу как виновника. Не удаляйте чужие адаптеры и не меняйте глобальные DNS для проверки.
5. Проверьте выключение и удаление выключенного приложения без общего переподключения, работу CS2 вне списка, затем обычный интернет после явного отключения SLX. Повторите используемый способ подключения и обычный сценарий после перезагрузки ПК.
6. Повторный ручной запуск SLX должен открыть текущее окно; повторный автозапуск в трей — сохранить одно окно. Закрытие второго запуска не должно выключать VPN.

Эта проверка нужна на машине друга: локальные тесты не воспроизводят его сеть. Работа при любых DNS, любом операторе или конфликте чужих сетевых программ не гарантируется; сбой должен сохранять точный статус и управляемое отключение.

## Локальная проверка и откат

SDK закреплён в `global.json`. Команды не публикуют выпуск:

```powershell
pwsh -NoProfile -File .\scripts\verify.ps1
if ($LASTEXITCODE -ne 0) { throw 'Проверки не прошли' }
pwsh -NoProfile -File .\scripts\build.ps1 -Candidate
if ($LASTEXITCODE -ne 0) { throw 'Кандидат не собран' }
```

Для отката отключите VPN, выйдите из SLX и установите опубликованную alpha.22 целиком. Сохранённые настройки совместимы. Разделённые обычные маршруты и новая проверка alpha.23 в alpha.22 отсутствуют; откат сам по себе не исправляет исходную проблему друга.
