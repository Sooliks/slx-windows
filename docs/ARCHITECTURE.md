# Boundaries

Alpha.24: Windows LibraryApplicationOrder owns presentation priority: browsers, Telegram, Discord, games/launchers,
then other applications. Exact executable metadata, bounded known catalogue categories and known game directories
classify cards only; they never create a routing match. Discovered/cached local cards precede catalogue recommendations.
Ordinal name/path tie-breaks keep equivalent results stable across source completion order and RU/EN switches. Running,
installed and shortcut results are ranked before their 300-path cap; DiscoveryScanner applies the same bounded order
before source publication, and Desktop applies it before its merged cap and twelve-card pagination. Progressive/cache
refresh reuses card instances and preserves explicit selection. Search, icons and discovery do not change live rules.

RecoveredApplicationPlan prepares a complete proposed selected-app plan before TunnelEngine adopts it. Windows
VersionedApplicationPaths.RefreshProtected reads recognized Discord/Roblox version siblings through held local
directory/executable handles without following reparse points, bounds candidates and preserves explicit disabled
siblings. ExactApplicationPlan then canonicalizes/validates the complete proposal. Cancellation or preparation failure
cannot partially replace the current/pinned application lists. Restore and recovery use one prepared list for WFP,
Xray, revision and durable intent; whole-PC mode does not gain selected-file dependencies. No generic name rule,
remote lookup, forced process termination or discovery-driven live update is introduced.

ApplicationUpdateTransaction marks ProtectionRecoveryRequired after any failed native application-filter stage:
initial union, rollback to Before after desired-intent save failure, final After, or final Before after the core's old
revision is confirmed. That flag invalidates the incremental baseline and stops further delta reconciliation/replay.
TunnelEngine clears the pending update, withdraws confirmed connection success and schedules full protected recovery.
Before remains authoritative when replacement was never attempted or the old core revision was confirmed; After is
the recovery intent after an attempted unknown/applied replacement. A lost core acknowledgement alone retains the
existing union and revision-read reconciliation; it does not force this native-baseline recovery path. Ordinary
application edits with a valid baseline continue to preserve the running core/TUN and unaffected sessions.

UserSettingsStore validates bounded preference structure and decrypted subscription snapshots with existing typed
contracts before Desktop consumes them, without checking installed files, resolving addresses or making requests.
A failed preference read latches writes off for that store instance; original bytes are preserved until the owner
restores the file/access and restarts. Desktop reads preferences and subscription independently, keeps a persistent
session-only Settings warning, and skips startup-registration reconciliation while preferences are unreadable.
An invalid cached subscription does not reset a valid InstallationId; explicit replacement can preserve that identity.
No reset, automatic repair or stored-data migration is introduced. Startup refresh labels retained cached profiles
after its own timeout or an active/busy replacement skip; explicit cancellation is distinct from a failed refresh.

Desktop separates subscription HTTP activity from a pending tunnel command: a refresh cannot relabel confirmed Off
as Disconnect or issue an off request merely because IsBusy is true. Explicit off during an active/uncertain tunnel
can supersede and cancel subscription HTTP, and generation fencing rejects its late result. Update-install admission
captures mutation generation and observation revision; its delayed read/error cannot replace a newer observation.
Only a current confirmed unprotected Off status grants the mutation lease; deadlines and cancellation remain bounded.
These contracts introduce no dependency, IPC, server or database change and do not prove installed packet continuity,
the friend's connection outcome, every destination, physical DNS behaviour or CS2 acceptance.

Alpha.23: Core XraySystemRoutes owns the four split-default prefixes and the existing two DNS host routes. Windows
TunnelRouteLookup shares unrestricted GetBestRoute2/GUID observation between TunnelDnsRoute and TunnelDataRoute;
it neither binds a probe socket nor edits routes. PublicIpv6Source limits the extra IPv6 read to a usable preferred
public source on an up interface. Service TrafficRouteProbe owns six-snapshot/three-second launch settling and typed
failure; TunnelHealth rechecks representative ordinary routes before retaining connection success. Owned Xray still
creates/removes routes, and initial rollback/established protection rules remain authoritative. Optional TrafficRoutes
is additive to IPC v2 and contains only bounded enums/numbers/time. DNS, proxy and traffic-route evidence are distinct.

Desktop MainViewModel.Status owns one concurrent bounded status read, last accepted read time and pending-action
diagnostics. Mutation generation plus observationRevision fence obsolete read success/failure without wall-clock
ordering or unknown mutation replay. All accepted status paths share AcceptStatus, including update-install admission
and retained live-routing failures.
When a read/unknown marker advances revision during a mutation, command Success/Code remains distinct from its obsolete
snapshot. Status owner fences old polls and performs one fresh bounded read linked to the operation deadline;
failure stays unknown and a superseding off cancels reconciliation. The completed command clears its pending label
before that read; periodic reads are gated until reconciliation ends. It never replays the mutation.
Presentation UiSingleInstance owns a user/session-scoped Local mutex and one show-only AutoResetEvent; App acquires
before model creation and releases on its dispatcher at Exit. Activation waits register after the window is ready,
cancel on disposal, and never carry service commands or arbitrary payloads.

Windows DisplayIconPath owns quoted-path/index parsing. ApplicationGroups.Refresh resolves only the existing known
package family in the current user's context; Desktop refreshes recognized versioned/package rules before a new
connection plan. Missing resolutions preserve exact intent for fail-closed validation. Discovery and icon lookup do
not alter an active route set by themselves. Dependency, driver, server and database ownership is unchanged.
Windows ExactExecutablePath owns the bounded local relative-handle walk with OBJ_DONT_REPARSE and no delete
sharing; it reads attributes only and holds ancestors/file through native ID comparison. ExactApplicationPlan prepares
enabled SelectedApplications paths only, permitting case/slash changes and requiring equal original/canonical WFP
IDs. Unsupported aliases/reparses and identity mismatch fail closed. Service prepares one canonical list before
start/update/restore/recovery policy or core replacement; current/pinned plans, Xray, WFP, revision and durable intent
use that same list. Whole-PC and disabled rows do not perform native path resolution. No arbitrary name matching.

Alpha.22: Core appends Checking to TunnelPhase while retaining all prior enum values. Service distinguishes the
periodic confirmation stage from actual Reconnecting: unconfirmed health clears ProbePassed but retains the owned
core/TUN, WFP policy and connection start; successful confirmation restores Connected without relaunch. Recovery
continues through the existing Reconnecting/StopChild/Launch path. Desktop treats Checking as active but unconfirmed,
keeps explicit off available, and provides distinct RU/EN copy. Help renders existing HealthCheck observations as
bounded target/result/time/HTTP metadata only. No additional network requests, raw logs, routes, timeouts, privileges
or stored-data fields are introduced. The new phase requires upgrading service and UI together through the installer.

Alpha.21: Core's typed TUN configuration adds host routes only for its two existing DNS addresses alongside the
defaults. The pinned Xray owns their lifecycle on its TUN; no independent route mutator or foreign-interface cleanup
is introduced. Windows TunnelDnsRoute still reads the unrestricted native route and now returns bounded numeric
prefix/route-metric evidence. Service waits for that owned route with bounded samples inside the existing per-attempt
and total DNS budgets, then performs the same unbound UDP exchange and after-answer route check. Final route failure
has its own VPN_DNS_ROUTE_FAILED code; a direct physical DNS response cannot establish readiness. Existing initial
rollback, established-session protection and explicit cancellation semantics remain authoritative. Desktop maps only
whitelisted copy and numeric diagnostic fields. Optional DnsCheck fields are additive to IPC v2; UI/service update
together, with no new action, stored-data shape, dependency, WFP or driver change.

Alpha.20: Core owns the exact HTTPS-only parallel DNS resolver policy and optional bounded DnsCheck observations.
Windows TunnelDnsRoute observes ordinary GetBestRoute2/LUID/GUID selection without changing routes or binding sockets.
Service TunnelDnsProbe owns unbound UDP, the existing deadlines, before/after owned-route checks and typed outcomes;
DnsProbePacket owns bounded query/answer validation. TunnelEngine retains the last check through rollback and resets it
at the next launch. Desktop formats only enums/numbers in safe diagnostics and maps VPN_DNS_FAILED to DNS-specific
localized copy. IPC v2 gains only an optional status field; no new action, stored-data shape, WFP or driver change.

Alpha.19: Windows UpdateTransport negotiates gzip only for the fixed release catalog and bounds both transferred and
decoded bytes. Release assets retain their exact byte/length/hash policy. ReleaseUpdateClient owns one 30-second
check deadline and returns UPDATE_TIMEOUT only for its own expired budget; caller cancellation still propagates.
Desktop maps only whitelisted update fault codes to localized copy, preserving existing offers and explicit install
consent. Core release selection, service/IPC, proxy choice and source/release trust boundaries are unchanged.

Alpha.18: ControlWorker keeps a bounded four-instance pipe pool with one first-instance anchor. ControlDispatcher
owns a short observation/ownership lock and a separate mutation gate. Authorized explicit-off admission interrupts
active readiness and prevents a start from slipping between validation and off admission; receipts remain bounded,
fingerprinted and SID-scoped. Status reads do not wait for network work. TunnelWork cancels health/launch readiness
without permitting concurrent lifecycle mutation. PendingOffCleanup retries durable-off, owned child/adapter shutdown,
WFP release and DNS-cache refresh until confirmed; IsConfirmedOff alone releases a controller after background cleanup.
InitialConnectionAttempt separates a definite failure from cancellation/unknown outcome. Only confirmed previously
unprotected attempts may roll back. The original failure code survives successful rollback; cleanup failure stays visible.
Windows OutboundInterface reads GetBestRoute2 before TUN creation and passes an exact current alias into typed Xray
configuration. The helper cannot change routes and rejects the SLX deterministic TUN identity, including renames.
StartupReadiness checks both existing authenticated HTTPS origins; owned TUN and protected DNS checks remain required.
Desktop unknown state offers explicit off without inferring an active tunnel or authorizing update installation.
The recovery script is an explicit administrative operation, outside UI IPC, with fixed installation/provider scope.
No stored-plan/IPC schema, server, subscription binding, driver or dependency version change.

Alpha.15: Desktop/Presentation owns Motion (one-shot attached animations and the motion policy), Chrome
(per-style hover fills), ScrollMemory (in-memory page offsets per view model) and the route-scene AmbientBackdrop.
MotionLifetime owns active clocks and their temporary lifecycle/policy subscriptions; completion and cancellation
remove clocks and handlers. ThemeManager adds/removes one owned system-color layer on High Contrast changes and
unsubscribes on application exit. Themes own all tokens; views never branch on the theme.
No Core/Windows/Service, IPC or stored-data format change.

Alpha.14: app edits use typed update-applications, distinct from explicit reconnect. Service compares the current
effective route set after full validation; metadata-only changes touch neither WFP nor core. ApplicationUpdateTransaction
owns union protection → durable desired intent → one Xray replacement → final app-only WFP delta. Response loss is
reconciled by reading a route revision; no blind mutation retry or global-restart fallback. Pending durable desired state
feeds normal recovery after a genuine health failure. A failed final native transaction invalidates the delta baseline;
the union stays protected until ordinary recovery or an explicit reconnect, rather than claiming applied success.
XrayRouteControl reaches the internal commander through authenticated HTTP CONNECT on the existing probe. API config
has no listen endpoint and exposes only RoutingService. Shared typed XrayRouteRule generates both JSON and pinned
protobuf. The optional ApplicationRevision on IPC v2 is confirmed only after routing/protection agree. Desktop matches
the final submitted revision and local intent generation; generic Connected cannot clear uncertain application state.

Alpha.12 application library: UserSettingsStore owns a separate bounded DPAPI discovery cache; DiscoveryScanner owns
independent source work with three workers and progressive batches. Desktop retains saved/partial results without
claiming freshness, reuses recent successful scans and validates explicit additions off UI. Scanning never mutates
selected routes. Shared asynchronous frozen icons use two workers and stable card instances. See APPLICATION_LIBRARY.md.

Alpha.11 resume: RestoredTunnelPlan prepares/validates bounded exact application siblings from existing encrypted intent;
it changes no endpoint, SID, storage or network policy. TunnelEngine uses one repaired list for WFP and core launch and
persists changed intent after committed protection. Desktop startup coordinates one connect-if-idle intent only for
configured --tray login. Dispatcher checks idle under its mutation gate and records active-state no-ops against replay.
Successfully loaded empty startup intent can retry only owned off-cleanup with pacing. Its distinct pending code keeps
the UI waiting without a connection request; only successful removal publishes Disconnected. Unreadable intent does
not arm cleanup, and explicit Stop cancels that startup retry even if it fails. New protection supersedes pending cleanup.
Desktop owns presentation and localization; Core owns typed contracts, subscription parsing and pure configuration.
Windows owns protected user storage, discovery and pipe transport. Service owns privileged core/network lifecycle.
Desktop cannot select a binary, command, shell, arbitrary core config, system file or service account.
The service validates plans and caller SID and serializes mutations. Server entitlement and HWID remain authoritative.
A second Windows user must not read/control another user's profile. Machine-wide TUN has explicit multi-session limitations.
SLX does not change production servers or publish private web repository content.
Credentials go through authenticated local IPC to memory-only Xray stdin. No plaintext config or raw core logs.
Xray and driver must have pinned provenance. Authenticated localhost proxy is only an internal readiness probe.
Connected means owned core + tunnel readiness + real proxy probe, not process start alone.

Alpha.5: Windows owns native WFP and protected resume storage; Service owns intent/lifecycle and retry. UI expands known application groups locally into ordinary validated exact-path AppRules. Persistent policy survives host/core stop; only explicit off/uninstall releases it. See NETWORK.md.

Alpha.9: desktop initialization reconciles the stored startup preference through the Windows registration owner. Service recovery observations are independent of connection success; the optional IPC field contains only a counter, enum and timestamp. It remains available after recovery, without storing core logs or changing routing/recovery behavior.

Alpha.10: LocalProbe owns authenticated proxy requests; ProbeRequest maps bounded HTTPS results to secret-free observations. HealthConfirmation owns the periodic confirmation policy, independently testable without network mutations. TunnelEngine retains lifecycle/WFP/core ownership and publishes no fresh success during an unresolved probe. Optional HealthCheck is additive to IPC v2; it does not grant any new command or pipe access.

Alpha.11: Windows `TrafficApplicationIds` resolves the complete native identity set before `TrafficGuard` starts filter replacement. Missing or denied selected paths have actionable codes; `TrafficProtectionError` exposes only an operation enum and numeric native result. Provider-scoped enumeration includes disabled owned filters and still checks the SLX sublayer. Service restore contains expected storage/native failures so control remains available; a loaded desired-on plan retains paced recovery. Failed WFP sessions close without removing persistent policy and can be reopened on the next attempt. No foreign-filter/adapter cleanup, provider migration or new network privilege is introduced.

`VersionedApplicationPaths` owns bounded local sibling lookup for recognized Discord/Roblox executable layouts. Desktop applies refreshed exact-path rules before building the next connect/reconnect plan. Existing paths remain selected; unresolved paths remain subject to service rejection. There is no executable-name wildcard or service-side arbitrary path remapping. The dispatcher preserves receipt fingerprint checks, keeps explicit idempotent off available when the bounded receipt cache is full, and releases its owner only after confirmed successful unprotected stop. The engine clears its owner after that completed stop; uncertain outcomes retain ownership. IPC remains v2 and UI/service are upgraded together.

Core owns SemVer comparison, same-repository release/asset policy and checksum parsing. Windows `ReleaseUpdateClient` owns bounded public HTTPS fetches, restricted asset redirects, streamed download, SHA-256 verification and explicit installer launch. Desktop owns startup/six-hour checking, saved reminder/automatic-check preferences and the offer/download/install states. A shared UI mutation lease checks the service for Disconnected and protection inactive before installer handoff and prevents connection changes during verification/launch. The installer is reverified while held open, Internet-zone metadata is retained, and UAC remains an explicit user step. Trust is in HTTPS and the authorized public GitHub repository; a checksum from that repository is integrity evidence, not a publisher signature. The application/installer remain intentionally unsigned; no elevated update daemon or updater IPC command is added. See UPDATES.md.

Desktop graphics use native WPF geometry with theme tokens. The route scene restates saved mode/app count only,
with a bounded 650 ms redraw after a choice changes and no settled rendering timer, animated connection claim or
fabricated traffic graph. High contrast omits the ambient drawing. The sidebar switches to an icon rail below
1080 WPF device-independent pixels while retaining tooltips and automation names; status/detail/code, application
controls and update states remain native WPF views. Olive/lime and Terminal themes preserve the SLX brand.
